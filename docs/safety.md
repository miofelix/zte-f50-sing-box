# 安全模型

## 操作范围

代理能力由官方 sing-box 提供。设备控制器处理 profile 指定热点接口的 TPROXY 流量、进程生命周期、watchdog 和自有规则，不接管设备自身 OUTPUT 流量。

开机自启动通过 root 用户启动脚本触发。项目不刷写分区、不修改 boot 分区，也不安装启动加载器。

## 所有权和回滚

项目使用独立链、mark、路由表和优先级。启动前检查冲突并保存诊断快照。停止和回滚先撤回拦截 hook，再精确删除自有链、路由和策略规则。

清理失败时，ownership 状态用于后续 `stop` 重试。系统防火墙快照只用于审计，不作整表恢复，以避免覆盖 Android、AdGuard 和 Tailscale 的规则。

## 试运行

`start N` 的租期为 30–3600 秒，默认 180 秒。核心和 watchdog 就绪后才发布拦截规则。未确认的会话到期自动清理；确认后的 watchdog 继续监测核心退出。

## 开机自启动

开机自启动默认开启。开关状态由 `autostart.disabled` 持久表示，关闭开关不停止正在运行的代理。立即停止代理使用 `stop`。

启动入口注册前检查 shell 语法、文件类型和标记，并保存 `0600` 备份。注册仅修改项目标记块，保留脚本其他内容、inode、属主和权限。F50 的入口由 UFI/Samba 启动链提供；缺少入口时停止注册并报告错误。

开机任务最多等待网络 180 秒，每个 boot ID 只尝试一次。任务先创建 120 秒试运行会话，通过 mixed 入站的 HTTP 204 检查后，才确认自己创建且开关开启的 session。检查失败或启动中关闭开关时，只清理该任务创建的会话；watchdog 负责超时与核心退出回滚。

## 凭据

节点导入使用隐藏提示或 stdin，私有 JSON、临时文件及备份使用 `0600`。`.local/`、`.cache/`、日志和设备配置不应提交到 Git。

## 验证范围

profile 按设备与固件验证。规则、profile 或网络环境变更时应检查相关行为。透明代理处理 TCP/UDP；ICMP 使用系统转发路径，UDP/QUIC 可用性取决于节点服务端。
